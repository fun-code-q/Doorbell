Security Model

QR Doorbell is built around the assumption that the server is honest-but-curious. The backend never reads guest message contents. This page documents what we protect, what we don't, and how.

End-to-end encryption

Each owner device generates a Curve25519 keypair on first launch. The public key is uploaded to owner_public_keys in Supabase; the private key never leaves EncryptedSharedPreferences (Android Keystore-wrapped). Guest messages are sealed with libsodium crypto_box_seal against every active owner public key for the house. The server stores ciphertext only.

Server-side trust boundaries

  • RLS-locked tables — anon can only call four whitelisted RPCs.
  • Edge Function HMAC — push-ring-notification verifies a Bearer token + HMAC-SHA256 of (timestamp ‖ body) plus a 5-min freshness window.
  • Per-token rate limit — 3 rings / 60 s, plus a per-door global cap (default 12 / hour).
  • Per-door geofence — haversine check; out-of-range rings are rejected.
  • Cloudflare Turnstile — invisible captcha for first-time visitors.
  • Audit log redaction — guest_message, ip_hash, lat/lon, public_key are masked as [redacted] in audit_log.details.

What we do NOT defend against

  • Compromised owner device — anyone who unlocks your phone can read messages and respond as you. Enable biometric unlock and the screen-lock PIN.
  • Physical access to the QR sticker — anyone within the geofence can ring. Rotate the QR token if a sticker leaks.
  • GPS spoofing by a determined attacker — Mock-location services + developer-mode override defeat geolocation everywhere. Geofence raises the bar; it does not eliminate the risk.
  • Side-channel attacks on libsodium / Android Keystore — out of scope.

Reporting a vulnerability

Use GitHub's Private vulnerability reporting tab on the repository. The maintainer named in CODEOWNERS is the security contact.

Operational security commitments

  • The Firebase Admin SDK service-account key never lives outside Supabase Edge Function secrets.
  • The production Android signing key is held outside developer machines (CI secrets / hardware token).
  • GitHub Actions are SHA-pinned via Dependabot. Branch protection requires CODEOWNERS approval + signed commits.
  • Production database migrations land via the db-migrations.yml workflow only after PR review + staging deploy.
  • Data Processing Addendum available for B2B customers (property managers).
